# SAGA + ReLaGS 工业场景世界模型 v2：方案完善、全场景实例提取与工程修正

## 0. 任务背景

当前项目位于 `paper_in` 目录。

我们已经完成了第一套工业场景世界模型方案：

`experiments/saga_relags_v1/`

本方案基于已有原生3DGS场景和M0工业设备包围框标注，实现了以下四个模块：

- A：基于SAGA共享亲和特征的设备级三维实例提取。
- B：基于已知工业设备类别的共享语言语义表达。
- C：参考ReLaGS场景图思想，利用工业空间先验构建设备间关系。
- D：基于类别和空间关系的设备查询及三维实例定位。

当前v1已经完成SAGA官方方法的适配与10,000步亲和特征训练，并在10个工业设备上进行了实例提取实验，其中9个具有较好的设备级查询展示效果，1个多层料架存在比较明显的分割问题。

同时，B模块已经构建8类工业设备的共享语义，C模块已经构建包含33个M0设备节点和2020条有向几何关系的场景图，D模块已经实现类别查询、关系查询及真实三维高斯实例的投影展示。

通过对实验报告、实际结果图和核心代码的审查，我们认为当前技术路线整体是正确的，具有继续研究和完善的价值。

**本次任务不是重新探索技术路线，也不是重新设计四个模块，而是基于现有v1方案进行有针对性的完善，形成覆盖更加完整、逻辑更加可靠、适合后续论文实验的v2版本。**

## 1. 必须贯穿整个任务的研究原则

### 1.1 充分利用已有工业先验

以下原则是整个研究的核心：

> 将某些论文原本需要解决的困难问题直接跳过，使用已有工业先验替代其复杂的前置阶段。只要剩余部分可以完成我们模块的核心目标，这篇论文就具有迁移价值。

当前M0已经提供了工业设备的类别、实例身份、粗空间范围和工业坐标系。

因此，不需要重新解决：

- 未知物体发现；
- 通用开放词汇类别识别；
- 自动设备实例身份匹配；
- 通用物体与部件层次发现；
- 工业场景坐标方向推断；
- 所有复杂视觉语义关系的自动识别。

应该充分利用这些已有信息，将主要研究工作集中在设备级实例提取、类别表达、空间关系构建和关系引导定位上。

### 1.2 明确当前论文的研究定位

本研究面向真实工业场景，目标是形成一篇研究范围合理的计算机科学中文期刊论文。

我们不追求构建一个能够解决所有三维场景理解问题的通用系统，也不要求四个模块分别具有复杂的算法创新。

只要能够在特定工业任务中解决具有实际意义的问题，并在后续实验中体现出相对于ReLaGS及其他相关方法的优势，就具有研究价值。

因此，不要为了追求局部结果的完美，而无限增加算法复杂度、训练成本和实验规模。

### 1.3 必须区分原始重建质量与实例提取质量

当前部分工业设备由于原始采集视角不足、严重遮挡、金属反光等原因，本身就没有在3DGS中被完整重建。

某些设备可能只有一半结构具有有效的三维高斯表达，甚至对应的真实二维观测视角也很少。

对于这些设备：

- 仍然需要进行实例提取。
- 仍然需要保存和展示其实际结果。
- 不应因为设备本身不完整就直接将其排除。
- 不应要求实例分割算法恢复原始3DGS中不存在的结构。
- 不应人为补造几何、修改高斯位置或生成不存在的设备部件。

如果一个设备只被原始3DGS重建了一半，但我们的算法能够将已经重建的部分准确地从场景中分离出来，那么对于当前设备实例提取任务而言，这仍然可以是有效结果。

评价时需要分别考虑：

1. 原始设备的三维重建完整程度。
2. 实例提取对已有设备结构的保留程度。
3. 实例提取对地面、背景和相邻设备的排除程度。
4. 提取后的实例是否具有设备级展示和查询价值。

**不要将原始重建不完整简单等价为分割失败。**

### 1.4 不追求所有设备都具有完美效果

真实工业场景中出现困难样例和失败样例是正常的。

我们需要的是：

- 大部分设备能够形成有效的独立实例；
- 已有设备结构能够得到合理保留；
- 明显无关的背景和相邻设备能够得到一定程度的排除；
- 不同设备能够保持独立的实例身份；
- 最终能够支持类别和关系查询；
- 困难设备及失败情况能够被真实记录。

对于某些经过合理尝试仍然无法取得明显改善的设备，应该保留当前实际结果并解释原因，而不是无限制地继续优化。

## 3. A模块：扩展至全部33个工业设备

这是本次任务最重要的部分，也是最高优先级任务。

v1已经完成：

- 32维SAGA共享亲和特征学习；
- 10,000步官方对比学习训练；
- 尺度门控网络训练；
- K=16近邻特征平滑；
- 原始高斯与亲和特征之间的对应关系检查。

现有训练曲线表明共享亲和特征已经表现出较好的训练收敛状态。

因此，本次首先直接复用：

`iteration_10000`

对应的亲和特征和尺度门控网络。

由于SAGA学习的是整个场景共享的亲和特征，而不是为每个设备分别训练一个独立模型，因此具备继续提取其他设备的条件。

**不要因为新增23个设备就默认重新训练SAGA。**

首先验证现有特征、门控参数和原始Gaussian ID是否与v2输入一致。

### 3.2 将实例提取范围从10个扩展到全部33个设备

读取完整的M0设备列表。

对全部33个设备建立统一的实例提取流程，包括：

- 物料车；
- 装配夹具台；

- 蓝色箱组；
- 立式移动冷风机；
- 工作台；
- 分隔式料架。

对于v1已经成功提取的9个设备，首先复用其已有实例、参考掩膜和提取参数，作为v2的初始结果。

不需要无条件重新优化这些已经具有较好效果的设备。

对于v1中失败的多层料架04，以及此前尚未处理的23个设备，重点完成：

1. 检查原始M0包围框及候选高斯。
2. 获取已有真实观测和虚拟观测。
3. 检查不同视角下设备的实际可见性。
4. 生成新的二维参考掩膜。
5. 提取合理的正提示点。
6. 使用现有SAGA亲和特征进行三维实例提取。
7. 保存原始Gaussian ID和独立实例PLY。
8. 对实际提取结果进行多视角渲染及质量检查。

所有33个设备都需要得到实际处理。

即使某个设备没有足够观测、只有部分重建结构或者最终分割效果不理想，也必须保留相应记录。

如果确实无法提取有效实例，应记录为失败或无法处理，而不是使用粗包围框结果冒充精细分割结果。

### 3.3 改进参考视角选择策略

v1中每个设备用于生成参考掩膜的视角数量较少，通常最多选择2个真实视角和1个虚拟视角。

同时，部分参考掩膜由于遮挡或混入相邻设备被拒绝，导致最终提取时可用的提示信息不足。

特别是多层料架04，最终只有3个有效正提示点。

因此，本次需要改善困难对象的参考视角选择策略。

但不要简单地为每个设备增加大量图像，也不要无意义地重复处理相似视角。

对于每个设备，应优先考虑：

- 设备在当前视角中的实际可见面积；
- 设备主体是否受到严重遮挡；
- 是否存在明显的相邻设备干扰；
- 当前视角能否观察到其他视角中不可见的设备部分；
- 是否能够获得不同方向的有效设备观测；
- 真实图像与完整场景虚拟渲染的互补性。

可以优先使用已经存在的多视角选择结果，并在必要时从原始306张训练图像中寻找补充视角。

需要明确区分：

- 已参与v1 SAGA亲和训练的视角；
- 未参与亲和训练、但属于原始训练集合的新增提示视角；
- 原始44张留出评价图像。

允许使用原始训练集合中的新增视角来生成实例提取提示。

但是新增提示只用于当前冻结特征的实例提取，不应擅自追加到v1训练监督或修改v1训练数据。

**禁止使用44张留出评价图像进行提示生成、阈值选择、尺度调整或实例修正。**

对于观测不足的设备，不强制要求达到某个固定视角数量。

如果只有一两个有效视角，就使用这些真实存在的有效观测，并明确记录局限。

### 3.4 改进提示点生成策略

当前v1主要通过SAM参考掩膜内部的距离变换提取正提示点。

这种方式能够获得较为可靠的主体提示，但对于细长设备、镂空设备以及多材质复合设备，提示点可能集中在少数局部区域。

因此，应该适当增加提示点在设备不同组成区域中的覆盖程度。

重点关注：

- 设备底座；
- 上部主要结构；
- 细长支撑结构；
- 不同材质的组成区域；
- 不同视角下能够观察到的互补区域。

提示点选择应该同时参考：

- M0粗空间范围；
- 当前高斯候选的可见性贡献；
- SAM参考掩膜；
- 已有真实图像中的设备结构。

不要为了增加提示数量而引入明显不可靠的提示。

v1采用多个正提示特征相似度最大值进行实例选择，因此受到污染的单个提示就可能引入错误高斯。

对新增提示，需要检查其是否实际位于目标设备上。

优先使用自动、可重复的提示生成规则。

如果确实需要少量人工或视觉审核辅助提示，应完整记录其设备ID、视角、坐标和用途，不得将其描述为完全自动生成的结果。

### 3.5 对效果不佳的设备进行原因诊断

不要看到某个设备效果不好就立即进行参数调整。

对于每个困难设备，首先检查问题属于哪一种类型。

类型A：原始3DGS重建缺失。

例如设备背部、底部或部分框架本身没有得到有效重建。

对于这种情况，保留真实结果，不进行几何补全。

类型B：M0候选范围不完整。

例如已有设备高斯位于粗包围框之外，导致后续亲和特征筛选无法获得这些结构。

应记录可能存在的包围框范围问题。

如果有明确证据，可以在v2中进行独立的小幅候选范围扩展实验，但不修改原始M0标注，也不能将扩展作为所有对象的默认处理方式。

类型C：参考视角或提示不足。

例如设备某些已经重建的部分没有获得有效提示。

优先通过补充真实观测、参考掩膜和空间分散的提示点解决。

类型D：亲和特征筛选导致的结构缺失或背景混入。

在有证据表明已有高斯可以被正确选择，但当前筛选策略不合适时，再检查阈值或尺度门控。

类型E：多种因素共同导致。

如无法明确区分，应记录不确定性，不要强行将所有问题归因于某一种原因。

对于每个困难设备，至少比较：

- 完整原始3DGS场景中的设备表现；
- M0直接裁剪的粗实例；
- SAGA提取后的实例；
- 对应真实二维图像中的设备可见部分。

注意，M0粗实例包含背景和其他高斯，并不是真值。

不能仅通过比较高斯数量判断缺失程度或分割准确率。

### 3.6 有限度地检查亲和度阈值

v1统一使用0.85作为实例提取的亲和度阈值。

当前定义为：

`score = (cosine_similarity + 1) / 2`

现有设备的结构和材质差异较大，因此统一阈值可能并非对所有设备都最合适。

但是不需要进行大规模超参数搜索。

建议首先：

- 使用原始0.85阈值完成全部33个设备的初始提取。
- 对具有明确筛选问题的代表性困难设备，有限比较0.80、0.85和0.90。
- 保持训练特征、提示点和其他条件不变，以便分析阈值的真实影响。

比较内容包括：

- 已有设备主体是否得到更好保留；
- 是否引入相邻设备；
- 是否增加地面及背景残留；
- 是否改善真实视角下的设备定位效果。

不要仅仅因为高斯数量增加，就认为分割效果提升。

如果统一阈值已经能够满足大部分设备的需求，则优先保留统一阈值。

不要为33个设备分别进行大量人工参数调整。

### 3.7 有限度地检查尺度门控

v1通过M0包围框对角线除以sqrt(3)估计设备尺度，并映射至SAGA训练尺度分布。

这种方式对于相对规则的设备具有一定合理性，但对于镂空、细长和非均匀结构设备，可能与实际可见结构的空间分布存在偏差。

因此，可以在少量具有明显问题的设备上，比较：

- 原始M0包围框估计尺度；
- 已有高质量参考掩膜对应的深度反投影尺度；
- 必要时适当相邻的尺度门控取值。

只有当尺度调整确实表现出明确的实例质量改善时，才考虑引入更加合理且可重复的尺度估计策略。

如果影响较小，则继续使用v1方式。

不要将尺度门控研究发展为新的独立算法模块。

### 3.8 处理全部33个实例之间的潜在冲突

v1只处理了10个设备，因此部分设备之间的高斯归属冲突可能尚未显现。

扩展到33个设备之后，需要检查：

- 不同M0候选范围之间的重叠；
- 同一个Gaussian ID是否被分配给多个设备；
- 相邻同类设备是否被错误合并；
- 新增设备是否对原有9个有效实例造成明显影响。

可以首先复用v1基于学习亲和度进行重叠候选分配的策略。

但需要注意，不同尺度门控及不同提示条件下的亲和度数值未必完全可比。

如果出现明显的错误归属，需要先检查具体案例，不要盲目采用更复杂的全局优化。

最终应保存统一的设备实例归属结果，同时记录冲突数量和冲突处理前后的变化。

### 3.9 关于重新训练SAGA的限制

本次默认冻结并复用v1已有训练检查点。

只有在以下因素已经得到充分检查后，才能判断是否有必要考虑重新训练：

- 原始重建质量；
- M0候选范围；
- 参考视角；
- SAM参考掩膜；
- 提示点覆盖；
- 亲和度阈值；
- 尺度门控。

如果发现多个新增设备由于共享亲和特征缺乏有效区分能力而出现系统性问题，可以在实验报告中提出重新训练的依据和建议。

但是，本次不要默认启动新的大规模训练，也不要覆盖现有训练结果。

## 4. A模块的结果评价方式

不要再简单地将设备划分为几何完整的成功设备和几何不完整的失败设备。

建议分别记录：

### 4.1 原始重建状态

- `well_reconstructed`：主要设备结构已经得到较好重建。
- `partially_reconstructed`：只有部分设备结构得到有效重建。
- `poorly_reconstructed`：原始重建质量较差。
- `uncertain`：暂时无法可靠判断原始重建程度。

### 4.2 实例提取状态

- `usable`：设备主体得到合理提取，具有独立实例展示价值。
- `partial_usable`：提取后的设备结构不完整，但能够明确表达已重建的目标设备，具有实际查询或展示价值。
- `needs_improvement`：存在比较明显的背景混入或已重建结构缺失，但仍具有分析价值。
- `failed`：无法获得具有合理设备身份和独立性的实例。

重建状态与提取状态必须分别记录。

例如：

某个设备原始状态为 `partially_reconstructed`，但最终实例提取状态为 `usable`，这是合理的。

某个设备原始重建比较完整，但SAGA只选择了一个小局部区域，则可能属于 `needs_improvement` 或 `failed`。

### 4.3 不同状态设备的展示原则

所有33个设备都应该出现在最终实验记录和结果图集中。

不得只展示表现最好的设备。

其中：

- `usable` 设备正常展示及查询。
- `partial_usable` 设备正常展示及查询，但标明局部重建或局部提取状态。
- `needs_improvement` 设备保留实际结果和诊断信息，并明确是否适合常规查询展示。
- `failed` 设备保留M0节点、失败结果和原因，不将其错误实例用于正常精细查询。

对于质量审核，应明确区分自动检查、Codex视觉检查和真实人工审核。

没有进行真实人工审核的结果，不得描述为已经获得人工真值认证。

## 7. D模块：修正设备查询与实例可用性之间的逻辑问题

当前D模块的类别解析、关系筛选及高斯实例返回机制整体合理。

但v1存在一个需要优先修复的逻辑问题：

C模块计算最近关系时，使用全部33个M0设备。

D模块执行查询时，却只允许通过分割审核的设备进入候选集合。

这可能导致真正满足空间关系的设备由于没有精细分割结果而被直接排除，从而返回空结果或者形成不完整的查询结果。

### 7.1 将设备查询与实例渲染分离

建议采用两个不同层次：

第一层：设备级查询。

在全部M0设备节点中进行：

- 类别匹配；
- 设备身份检索；
- 空间关系筛选；
- 最近设备定位。

第二层：精细实例获取。

根据第一层已经确定的设备ID，检查是否存在对应的有效三维高斯实例，并进行渲染或投影展示。

设备级查询结果不应因为精细实例暂时不可用而消失。

例如：

用户查询距离装配夹具台01最近的物料车。

如果真正最近的物料车没有完整的精细分割实例，那么系统仍然应该返回：

- 正确的设备ID；
- 设备类别和名称；
- M0空间位置；
- 实际满足的最近关系；
- 当前实例提取状态；
- 精细实例是否可用。

如果存在部分可用的三维实例，则可以展示其真实局部结果。

如果没有可用的精细实例，则明确说明，只能提供当前设备位置和粗空间信息。

不能为了获得一个可以渲染的实例，就将第二近的设备冒充为真正最近的设备。

同样，也不能将M0直接裁剪结果冒充为SAGA精细分割结果。

### 7.2 完善有限自然语言解析

保留现有规则解析和类别匹配方式，不需要引入复杂的大语言模型。

但应该检查：

- 不支持的关系表达是否被错误地退化为普通类别查询；
- 参照对象不存在时是否给出明确状态；
- 查询包含多个同类参照对象时，结果语义是否明确；
- 不属于已知类别的查询是否能够合理拒绝；
- 关系不存在时是否正确返回空结果；
- 是否存在设备名称或类别别名之间的匹配冲突。

对于无法解析的关系表达，应明确返回不支持或无法解析，而不是默默忽略关系条件。

只需要保证当前论文所涉及的主要查询表达可靠，不需要实现通用自然语言理解。

### 7.3 增加具有针对性的查询测试

重点验证：

1. 普通类别查询能够返回全部已知类别匹配设备。
2. 同类设备具有独立实例身份。
3. 最近关系能够正确返回真实最近设备。
4. 左右、前后、邻近关系能够合理筛选目标。
5. 部分重建设备仍然能够被正确定位。
6. 分割失败设备仍然能够作为查询结果或关系参照。
7. 精细实例不可用时能够正确返回状态。
8. 不存在的设备或关系能够产生合理空结果。
9. 不支持的表达不会被错误解释。
10. 查询阶段不需要重新运行SAM或SAGA分割。

应针对v1发现的最近关系候选范围冲突设计专门的回归测试。

优先使用实际场景中的真实案例。如果当前场景不存在某种边界情况，可以额外使用明确标记的合成单元测试验证查询逻辑。

不能将合成逻辑测试描述为真实工业实验结果。
