# M0 → M1–M5 输入契约

后续实现应只获得冻结版本中 `priors/` 及来源清单，评价脚本另行获得 `ground_truth/`。不要把整个可写 M0 根目录直接作为算法输入。

| 模块 | 可读取 | 不可读取 / 本阶段未实现 |
|---|---|---|
| M1 工业高斯空间表示 | 来源清单对应的基础/MWP PLY、COLMAP、训练图像、工业坐标与区域 | 旧地面/区域估计、旧语义分组；M0 不重训或改写原 PLY |
| M2 多视角对象建模 | confirmed 对象、训练视角 confirmed 可见掩膜、相机、可选粗略 ROI | 留出掩膜、旧设备高斯集合、旧分组；M0 不生成最终实例索引或最终对象 OBB |
| M3 视觉与文本融合 | confirmed 对象描述及字段来源、同一 object_id 的 confirmed 训练掩膜区域 | OpenSeg/CLIP 历史特征、留出掩膜、语义评价查询；M0 不计算 CLIP 或最终融合特征 |
| M4 语义场景图 | 工业坐标、区域、关系 schema、必要 known_relations，后续 M2/M3 输出 | reference_relations、旧图/预测边；M0 不预测完整空间关系 |
| M5 语义与关系查询 | M3 语义索引、M4 图、固定关系词汇、运行时用户查询 | 预置评价查询答案、查询到 object_id 的硬编码表；M0 不实现正式检索/推理 |

## 加载时必须检查

1. 校验 `FREEZE.json` 中的文件 SHA-256，记录版本 ID、来源几何哈希和 schema_version。
2. 对象清单仅采用 `status == confirmed`；区域必须 `include == true` 且已确认。
3. 掩膜只采用正确 scope、`review_status == confirmed` 且 visibility 为可见状态的记录。读取 `mask_path` 时验证尺寸及 image_sha256。所有掩膜保留原分辨率，不根据网页显示尺寸再次缩放。
4. 以 `object_id` 关联多视角；不能用类别名合并同类设备。candidate_region 只限制搜索，不能当作最终预测位置。
5. 工业坐标中的左右基于 +X，不随当前相机改变。主通道方向为 +Y。缺少尺度时不把数值解释为米。
6. 粗略 ROI 是候选搜索范围，不是最终设备包围盒或高斯归属真值。

## 独立评价

- M2：在固定原始 heldout 图像投影后，与人工确认的 heldout mask 计算指标。不得用它做高斯关联、参数选择或 M3 融合。
- M3：使用独立语义查询评估对象检索；输入的类别字段正确性不能算作自动识别准确率。
- M4：使用 true/false 关系，排除 unknown、未确认和已作为先验输入的记录。对称与互逆关系也按同一事实去重。
- M5：依据预先冻结的 expected_object_ids 评价，允许多答案/无匹配，不能把答案写进检索规则。

M0 提供数据隔离和导出约束；研究过程仍需保证后续开发者没有利用评价集调参。没有在这里实现 M2–M5，也没有生成可宣称为人工真值的自动关系标注。
