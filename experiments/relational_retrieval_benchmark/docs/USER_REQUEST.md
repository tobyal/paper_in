# 工业场景关系引导三维实例检索：外部方法对比实验

## 1. 研究背景与实验目标

当前项目位于 `paper_in` 目录。

我们已经完成了工业场景关系引导三维实例检索方法的实现，最终版本为：

`experiments/saga_relags_v2/`

该方法基于已有工业3DGS场景、M0设备粗粒度先验及多视角RGB图像，通过以下技术模块实现关系引导的目标实例检索：

- A：基于SAGA共享亲和特征的工业设备级实例提取。
- B：基于CLIP的工业设备类别共享语义表达。
- C：基于工业空间先验的显式设备关系构建。
- D：类别与空间关系共同约束下的三维设备实例检索。

目前已经完成全部33个工业设备的实例提取尝试，包含8种设备类别、33个设备节点、2020条有向空间关系，其中30个设备具有可用或局部可用的三维实例。

具体实现和实际结果参考：

- `experiments/saga_relags_v2/README.md`
- `experiments/saga_relags_v2/EXPERIMENT_REPORT.md`
- `experiments/saga_relags_v2/MODIFICATION_REPORT.md`
- `experiments/saga_relags_v2/docs/GALLERY.md`

当前论文暂定研究方向为：

**面向工业场景的空间关系引导三维高斯实例检索方法。**

工业场景世界模型构建是本文的宏观研究背景，论文具体聚焦于其中的空间关系表达和设备实例检索技术。

A、B、C、D是实现关系引导实例检索的技术环节，而不是四项独立的研究任务。

本次实验的核心参考是ReLaGS原论文第4.2节：

**Evaluation on Open Vocabulary Instance Segmentation with Relationship Guidance**

论文地址：

https://arxiv.org/html/2603.17605v1

请首先阅读该部分及Table 2，理解其任务定义、对比方法、查询输入和评价方式。

我们的实验沿用其核心研究思路，将任务适配到具有已知设备类别及工业空间先验的真实工业场景中。

本次唯一的核心实验任务是：

**给定目标设备类别、空间关系和参照设备，在三维工业场景中检索满足关系约束的目标设备实例。**

## 2. 本次对比实验的基本原则

本次实验采用的是：

**现有论文方法在真实工业场景中的直接应用对比，而不是帮助其他论文重新设计一套适用于工业场景的算法。**

具体执行思路为：

1. 阅读对比论文的原始方法及实验协议。
2. 查找并复用已有模型、数据和运行环境。
3. 按照官方实现所需的格式接入我们的工业场景。
4. 将统一关系查询转换为各方法支持的输入形式。
5. 调用各方法原有算法及正常配置执行查询。
6. 保存真实输出，并转换为统一的对比结果。

对于外部方法，主要开展数据格式、文件路径、相机参数、查询接口和结果导出方面的适配。

核心算法、网络结构、查询机制及正常参数配置沿用原论文和官方实现。

本次重点是考察这些通用三维语义及关系检索方法直接应用到工业场景时的实际表现，并与本文方法进行比较。

所有实验结果应如实保存，包括表现较好、表现一般、检索错误和空结果。实验的目的不是预设各方法的最终排名，而是通过实际结果分析工业先验引导方法的优势及局限。

## 4. 确定本次对比方法

本次只执行以下四种方法：

| 方法 | 发表年份 | 技术路线 |
|---|---|---|
| LangSplat | CVPR 2024 | 三维高斯语言特征场 |
| THGS | ACM MM 2025 | 层次化高斯语义表示 |
| ReLaGS | CVPR 2026 | 显式关系场景图 |
| Ours | 本文方法 | 工业先验引导的空间关系实例检索 |

选择这三个外部方法的原因是，它们均属于ReLaGS原论文关系引导实例分割实验中的相关方法，能够代表不同的三维语义及关系检索技术路线。

其中：

- LangSplat代表连续三维语言特征表达。
- THGS代表层次化三维实例语义表达。
- ReLaGS代表具有显式关系建模能力的三维检索方法。
- Ours代表利用工业先验进行设备实例表达和空间关系检索的方法。

本轮任务仅为外部方法整体对比。

内部消融实验、M0直接裁剪基线、无关系约束版本及RelationField复现暂时留到后续阶段。

## 10. 建立统一关系查询测试集合

### 10.1 核心任务定义

所有方法统一面对以下关系检索任务：

给定：

`q = <s, p, o>`

其中：

- `s`：目标设备类别。
- `p`：空间关系。
- `o`：参照设备类别。

输出满足关系约束的目标三维区域或设备实例集合。

对于LangSplat和THGS，将三元组转换为完整英文语言描述。

对于ReLaGS和Ours，使用相应的关系三元组或等价查询表达。

### 10.2 统一设备类别

当前工业场景包含以下8种设备类别：

| 中文类别 | 建议英文表达 | 实例数量 |
|---|---|---:|
| 物料车 | material cart | 6 |
| 装配夹具台 | assembly fixture table | 3 |
| 带黑色工件的夹具台 | fixture table carrying a black workpiece | 5 |
| 多层料架 | multi-tier material rack | 9 |
| 蓝色箱组 | group of blue storage bins | 3 |
| 立式移动冷风机 | upright portable air cooler | 3 |
| 工作台 | workbench | 2 |
| 分隔式料架 | compartmented material rack | 2 |

请读取v2实际类别配置，并参考原始工业RGB图像确认英文表达。

统一使用自然、明确且能够描述实际设备外观的类别名称。

针对不同方法，仅进行必要的接口格式转换，统一保留查询的目标对象和关系含义。

### 10.3 统一关系类型

本轮正式外部对比主要采用以下五种空间关系：

| 空间关系 | 英文表达 | 建议查询数 |
|---|---|---:|
| 左侧 | left of | 5 |
| 右侧 | right of | 5 |
| 前方 | in front of | 5 |
| 后方 | behind | 5 |
| 邻近 | near / close by | 5 |
| 合计 | — | 25 |

具体关系词映射以各方法原有接口为准。

请检查ReLaGS官方关系词表及关系语义，建立固定映射表，确保三元组与完整文本表达相同的空间含义。

本文额外实现的 `nearest_to` 暂时作为后续工业应用展示内容，本轮主要采用上述共同空间关系。

### 10.4 查询设计原则

请结合当前工业场景的真实设备分布、M0粗空间信息和原始RGB图像设计查询集合。

重点体现工业场景中的一个核心问题：

**同类设备具有相同或相似语义，仅依靠类别信息难以确定目标，需要进一步利用空间关系进行区分。**

因此，优先选择存在多个同类设备、且关系条件具有实际区分作用的查询。

同时兼顾不同设备类别、不同空间关系、局部重建设备和具有一定困难的实际场景。

建议约25条查询。实际数量可以根据场景中有效关系的分布进行合理调整。

查询设计时参考以下形式：

- 冷风机左侧的物料车。
- 工作台附近的多层料架。
- 物料车后方的装配夹具台。
- 分隔式料架右侧的蓝色箱组。
- 多层料架前方的带黑色工件的夹具台。

这些仅为形式示例，实际查询必须结合真实场景确定。

### 10.5 参照对象及多实例问题

当前场景中的8类设备均具有多个实例。

为了使各方法面对相同的查询任务，正式对比主要采用公开可描述的类别及外观信息，而不是只有M0能够识别的人工设备编号。

当一个参照类别包含多个设备时，本轮默认采用以下集合查询语义：

如果某个目标设备与至少一个符合参照描述的设备满足指定空间关系，则该目标设备属于查询结果集合。

同一查询允许包含一个或多个正确目标设备。

优先选择确实能够缩小同类候选范围、且具有明确空间含义的查询。

如果某些关系在当前场景下无法形成足够具有区分性的查询，可以适当减少该关系的查询数量，并记录原因。

## 13. 评价指标

### 13.1 与ReLaGS原论文评价思路保持一致

ReLaGS原论文第4.2节采用关系引导三维实例分割任务，并使用3D mIoU作为核心指标。

由于原论文使用ScanNet++数据集，具有独立的三维点级分割真值，并建立了高斯与真值点云之间的对应关系，因此能够直接计算三维IoU。

我们的工业场景使用已有3DGS和2DGS模型，目前没有独立三维点级分割真值。

因此，本次将其评价方式适配为：

**多视角投影mIoU（Multi-view Projection mIoU）。**

该指标仍然评价关系引导实例检索结果与正确目标区域的一致程度，仅将计算空间从三维点云转换为真实图像的二维投影空间。

### 13.2 核心指标：投影mIoU

对于查询q及评价视角v：

`IoU(q,v) = Intersection(P(q,v), G(q,v)) / Union(P(q,v), G(q,v))`

其中：

- `P(q,v)`：该方法返回的预测掩膜。
- `G(q,v)`：独立人工确认的正确目标掩膜。

先计算每条查询在有效评价视角上的平均IoU，再对全部查询进行平均，得到最终投影mIoU。

采用查询级平均方式，使每条查询具有相同权重。

当真值目标可见、但方法返回空预测掩膜时，IoU记为0。

对于无法建立有效真值、或者尚未进行标注确认的视角，标记为待评价。

### 13.3 辅助指标

Precision：

`Precision = TP / (TP + FP)`

用于分析预测区域中相邻设备和背景的混入程度。

Recall：

`Recall = TP / (TP + FN)`

用于分析正确目标设备区域的保留程度。

Query Time：

用于分析各方法完成在线关系查询的实际效率。

建议记录：

- 模型加载耗时。
- 在线查询耗时。
- 目标结果渲染耗时。
- 完整查询至输出掩膜的总耗时。

由于不同方法可能在三维场景级或逐视角进行查询，应同时保留统一评价视角下的端到端输出时间。

在相同服务器硬件条件下完成计时，并适当进行预热及重复测量。

### 13.4 当前人工真值状态

当前工业场景尚未建立独立的精细分割人工真值。

因此，本轮首先完成所有方法的真实查询、预测掩膜生成和定性对比。

同时实现可供后续使用的评价脚本及真值数据接口。

建议建立：

`evaluation/ground_truth/`

用于后续保存人工确认的目标掩膜及设备ID。

如果服务器中已经存在与本次查询及评价视角对应的独立人工真值，应先核实其来源和适用性，再进行正式指标计算。

当前没有独立真值的情况下，mIoU、Precision和Recall统一记录为 `Pending GT`。

SAM自动生成掩膜、M0包围框和各方法自身的预测结果可以作为辅助查看材料，但不作为已经确认的人工真值。
