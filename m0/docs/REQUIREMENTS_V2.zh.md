# M0 Web平台重构：三维工业场景先验数据准备

## 一、项目背景与核心目标

当前工程：

`/mnt/sda/ubuntu/lkx/papers/paper_in`

GitHub：

https://github.com/tobyal/paper_in

参考论文：

**ReLaGS: Relational Language Gaussian Splatting（CVPR 2026）**

当前已经完成ReLaGS的Baseline 0、R1复现以及第一版M0 Web平台开发，Web代码位于`m0/`目录。

但是，现有Web平台存在以下问题：

- 以二维图像为主要操作入口，寻找和标注工业设备非常不直观。
- 功能页面过多，人工操作流程复杂。
- 收集了大量后续算法不一定需要的信息。
- M0数据准备与论文核心算法之间的边界不够清晰。

现在需要重构现有Web平台。

**M0仅负责数据准备、研究范围限定及工业先验构建，不属于论文的核心算法流程。**

我们的研究思路是基于ReLaGS，通过增加少量工业场景先验降低算法难度，而不是在M0中提前完成ReLaGS的核心研究任务。

M0最终只需要提供：

1. 工业场景整体空间范围及坐标参考。
2. 需要建模的工业对象及其粗略三维范围。
3. 工业对象的基础名称和文本描述。
4. 可选的单视角参考掩膜，用于少数难以区分的设备。

完成以上信息后，即可进入后续论文方法。

## 二、严格明确M0与后续论文方法的边界

后续论文方法暂定为：

| 模块 | 研究内容 |

| 粗略三维设备框 | 提供 | 使用 |
| 对象基础名称及描述 | 提供 | 使用 |
| 单张参考掩膜 | 可选提供 | 使用 |
| 自动多视角选择 | 不作为M0建模任务 | M2完成 |
| 批量SAM分割 | 不执行 | M2完成 |
| 多视角高斯关联 | 不执行 | M2完成 |
| Superpoint及局部分组 | 不执行 | M2完成 |
| 精确三维实例提取 | 不执行 | M2完成 |

当前不考虑实验评价、留出掩膜标注、评价查询及关系真值构建。

## 四、重新设计Web平台整体结构

取消原有七步主导航。

新平台只保留两个主要工作页面：

### 页面一：工业场景确定

用于调整整个工业场景包围框、确定有效研究空间及工业坐标参考。

### 页面二：工业对象确定

用于在三维场景中创建工业对象、调整粗略三维设备框、填写基础文本描述。

单视角SAM参考掩膜作为对象编辑中的可选辅助工具，不作为独立主页面。

另外提供简洁的保存、检查及导出入口。

整个Web平台必须以三维工业场景为主要操作对象，而不是以二维图像为主要操作对象。

## 五、核心功能一：三维工业场景与三视图工作台

这是本次重构最重要的基础功能。

### 5.1 场景显示

直接加载当前已完成的工业高斯场景，提供四个联动观察窗口：

- 自由旋转的三维场景。
- 俯视图。
- 正视图。
- 侧视图。

支持：

- 旋转。
- 平移。
- 缩放。
- 视图重置。
- 场景包围框显示。
- 对象包围框显示。
- 选中对象高亮。

优先复用已有2DGS渲染能力。

注意当前场景使用2DGS表示，不要假设普通3DGS Web渲染器能够直接兼容。

如果完整高斯Web渲染实现成本过高，允许采用高质量彩色高斯中心点云结合服务器端真实高斯渲染的方式，但必须能够清楚辨认工业设备。

不能继续仅使用原来的稀疏点云二维投影作为主要交互方式。

三维场景和三个正交视图必须使用统一坐标系，并保持包围框状态同步。

### 5.2 三视图包围框编辑

提供统一的三维包围框编辑工具。

支持通过俯视图、正视图和侧视图拖动包围框边界，调整：

- 中心位置。
- 长度。
- 宽度。
- 高度。

三视图中对同一个包围框的修改必须实时同步。

允许对场景整体包围框进行必要的方向调整，使其能够与实际车间地面和主要通道方向对齐。

完成工业坐标系初始化后，设备框默认使用统一工业坐标系下的轴对齐包围框，以降低标注操作难度。

所有操作尽量通过鼠标完成，不要求人工输入三维坐标数值。

## 六、核心功能二：工业场景空间范围确定

### 6.1 人工操作

平台初始化时，自动生成一个大致覆盖有效高斯场景的包围框。

允许我们通过三视图调整这个框，排除：

- 重建外围噪声。
- 不需要研究的远处背景。
- 无关场景结构。
- 其他无效空间。

同时确认：

- 包围框底面与车间地面的对应关系。
- 竖直向上的方向。
- 车间主要前进方向。

不再要求人工分别选择大量地面参考点、坐标原点及原始COLMAP坐标轴。

如果无法可靠地自动估计地面，可以提供简洁的辅助选点功能，但不要将其作为默认的复杂操作流程。

### 6.2 自动计算

在用户确认场景框及空间方向后，后台自动计算：

- 场景包围框中心。
- 场景长宽高。
- 工业参考坐标系。
- COLMAP到工业坐标系的转换矩阵。
- 地面参考平面。
- 场景范围内的高斯基元索引。
- 场景相对尺寸。

坐标系必须为明确的右手坐标系，例如：

- +X：右侧。
- +Y：前方。
- +Z：上方。

不能直接假设原始高斯坐标轴已经与车间方向一致。

场景包围框的底面只能在确认为地面后作为地面参考。

当前没有实际物理尺度标定时，全部尺寸和坐标继续使用SfM相对单位，不得解释为米。

### 6.3 输出

保存：

```text
scene/
├── scene_bbox.json
├── coordinate_system.json
├── coordinate_transform.npy
├── scene_gaussian_indices.npy
└── scene_overview.jpg
```

这里只限定场景空间范围，不进行工业对象分割。

暂时不要求进一步划分多个工业功能区域。

## 七、核心功能三：工业对象粗略三维范围标注

这是M0中最主要的人工操作。

### 7.1 操作流程

完成场景范围确定后，我们直接在三维工业场景中选择需要研究的工业设备。

每次创建对象时：

1. 点击三维场景中目标设备的大致位置。
2. 自动创建一个初始三维包围框。
3. 通过三视图调整包围框的位置和大小。
4. 输入工业对象名称。
5. 输入简短的基础视觉描述。
6. 保存该对象。

然后继续创建下一个对象。

整个过程不要求先选择二维图像，也不要求先绘制二维参考框。

### 7.2 包围框要求

对象包围框只需要大致包含目标设备。

允许包围框中存在：

- 少量地面。
- 局部背景。
- 少量相邻设备结构。
- 其他需要由后续算法排除的高斯基元。

不需要人工使三维框精确贴合设备表面。

**粗略三维包围框是M2的搜索空间约束，不是最终对象实例或最终精确三维包围盒。**

禁止在M0中根据这个框直接将内部全部高斯保存为最终设备实例。

允许显示框内候选高斯，辅助人工调整空间范围，但必须明确标记为粗略候选。

### 7.3 对象管理

左侧提供简洁的工业对象列表。

支持：

- 创建对象。
- 选中对象。
- 编辑对象框。
- 修改名称和描述。
- 隐藏或显示对象框。
- 删除对象。
- 查看已确认状态。

每个对象自动生成永久唯一的object_id。

相似设备必须创建为不同实例。

默认采用完整设备级建模。对于堆叠物料，可以按实际情况定义为一个物料箱组。

不要求进行细粒度部件标注，也不要求覆盖整个车间的全部对象。

第一轮只选择约5—8个代表性工业对象，之后按需要扩展。

## 八、核心功能四：工业对象基础语义信息

每个工业对象只需要人工确认以下信息：

- 中文名称。
- 英文名称。
- 一段简短的基础视觉描述。

例如：

```json
{
  "object_id": "object_001",
  "name_zh": "工业冷风机",
  "name_en": "industrial air cooler",
  "description_zh": "灰色矩形设备，正面具有通风格栅。",
  "description_en": "A gray rectangular industrial air cooler with a ventilation grille."
}
```

上述内容只是数据格式示例，不代表已经确认的真实设备。

允许由Codex或视觉模型根据参考图像辅助生成候选描述，再由人工确认。

不要求人工填写大量独立属性字段。

不需要：

- 设备制造商。
- 设备型号。
- 功率与生产参数。
- 工艺流程。
- 内部结构。
- 当前运行状态。
- 复杂功能知识。
- 设备之间的空间关系。

对象文本只描述该对象本身，不提前写入后续M4需要计算的左右、邻近等空间关系。

未经确认的信息保留为空或unknown，不要虚构。

M0不计算CLIP特征，也不进行最终视觉语言融合。

## 九、可选功能：单视角SAM参考掩膜

保留现有SAM分割功能，但大幅降低它在M0中的使用范围。

### 9.1 默认方案

对于大部分边界明确的工业设备，M0只提供粗略三维框和基础文本描述。

不需要SAM掩膜即可完成对象标注。

后续论文方法M2负责根据三维框自动选择视角、生成提示并进行多视角SAM分割。

### 9.2 特殊对象

对于外观相似、相互遮挡或者粗略三维框难以充分表达目标身份的设备，允许额外提供一张经过确认的二维参考掩膜。

操作方式：

- 根据当前设备粗略三维框及相机参数，自动推荐少量训练图像。
- 人工选择其中一张最清晰的图像。
- 自动投影生成SAM候选提示框。
- 使用现有SAM工具完成参考分割。
- 必要时通过正负提示点或画笔进行修正。
- 保存最终参考掩膜。

这里的视角推荐仅用于获得可选的单张参考图像，不是后续M2正式的多视角建模流程。

只允许使用训练视角，不能使用留出评价图像。

### 9.3 限制

M0不需要：

- 对每个对象执行批量多视角SAM分割。
- 完成人工跨视角掩膜标注。
- 将掩膜反向融合到三维高斯。
- 生成最终三维对象索引。
- 进行三维实例补全与优化。

SAM参考掩膜是可选输入，不应成为保存对象或导出M0的必填条件。

## 十、界面布局

尽量采用简洁的三维标注工作台布局。

页面主要包含：

- 左侧：工业对象清单。
- 中央：三维场景及三个正交视图。
- 右侧：当前对象名称、基础描述及包围框状态。
- 顶部：新建对象、保存、场景设置、导出。
- 底部或弹窗：可选二维参考图像及SAM工具。

默认隐藏：

- 高斯索引详情。
- 相机参数。
- 坐标变换矩阵。
- 关系阈值。
- 模型运行配置。
- 详细日志。
- 历史修订数据。

这些技术信息可以保存在后台，必要时通过高级设置查看。

用户不需要理解ReLaGS、COLMAP或高斯渲染的内部细节即可完成标注。

## 十三、开发顺序与验收标准

### 第一阶段：三维工作台

优先完成：

- 加载实际工业高斯场景。
- 三维自由浏览。
- 三视图联动。
- 场景包围框编辑。
- 工业坐标参考确定。

首先保证我们能够直观理解和操作整个工业车间。

### 第二阶段：工业对象标注

完成：

- 三维对象创建。
- 粗略设备框调整。
- 对象清单管理。
- 基础文本描述。
- 保存及重新加载。

使用真实工业设备完成至少一个完整对象的操作闭环。

### 第三阶段：可选SAM参考

复用已有SAM推理和编辑工具，完成三维对象到单张参考图像的辅助标注流程。

不实现正式多视角建模。

### 第四阶段：数据导出

完成新版M0数据格式、数据检查、版本冻结及后续算法输入接口说明。

验证以下情况：

- 没有SAM参考掩膜的对象可以正常保存和导出。
- 相似设备能够独立创建并保存。
- 三视图中的包围框完全同步。
- 刷新页面后对象框及语义信息正确恢复。
- 导出的空间框与实际三维场景位置一致。
- 不存在最终三维实例、融合语义或场景图等后续算法输出。
- 原Baseline 0和R1不受影响。

请首先检查现有Web代码和实际服务器数据，然后直接进行重构、运行和验证。

最终提供实际访问方式、代码修改说明、数据接口说明及真实测试结果。

**本次开发始终遵循三个核心原则：以三维场景为操作入口，以粗略工业对象先验为最终输出，以减少人工操作和保留后续论文方法空间为目标。**
