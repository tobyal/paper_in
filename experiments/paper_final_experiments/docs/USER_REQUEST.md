# 面向论文撰写的工业空间关系引导三维实例检索：补充实验与实验图表构建

## 一、任务背景

当前项目位于 `paper_in` 目录，GitHub仓库为：

https://github.com/tobyal/paper_in

目前已经完成本文的主体方法实现：

`experiments/saga_relags_v2/`

以及外部方法对比实验：

`experiments/relational_retrieval_benchmark/`

当前论文暂定题目为：

**《面向工业场景的空间关系引导三维高斯实例检索方法》**

Spatial Relation-Guided 3D Gaussian Instance Retrieval for Industrial Scenes

本文以工业场景世界模型构建为宏观研究背景，具体聚焦于空间关系引导的工业设备三维实例检索。

本文的核心研究任务是：

给定目标设备类别、空间关系和参照对象，在已经重建的工业三维高斯场景中，检索并返回满足关系条件的目标设备三维实例。

当前研究主要解决两个技术困难：

1. 工业设备结构复杂、组成部分多、相邻设备密集，通用三维实例表达容易出现设备粒度不统一、局部结构缺失和相邻设备混入等问题，影响关系主体的可靠表达。
2. 工业场景中存在大量外观及类别相似的设备，仅依靠类别语言语义难以准确区分具体设备，需要进一步利用明确的空间关系实现目标实例检索。

本文方法由现有A、B、C、D四个实现模块组成，但正式论文中将其组织为两个主要技术阶段。

### 第一阶段：工业先验引导的三维关系实体构建

对应现有A、B模块。

利用已有M0设备身份、类别和粗三维包围框，结合多视角互补观测、SAM参考掩膜、空间分散提示及SAGA共享亲和特征，获得具有明确设备身份和类别语义的独立三维高斯实例。

### 第二阶段：工业空间关系建模与实例检索

对应现有C、D模块。

利用统一工业坐标系及设备空间先验构建显式空间关系图，将类别匹配和空间关系筛选相结合，最终返回满足查询条件的三维高斯实例。

A、B、C、D是实现最终关系检索任务的技术环节，而不是四项独立研究任务。

# 六、E02：主要方法机制消融实验

## 6.1 实验目的

在相同M0工业先验条件下，验证本文两个主要技术机制对最终关系引导实例检索的实际贡献。

即：

1. 精细三维关系实体表达的作用。
2. 空间关系约束的作用。

这是本轮最重要的新增定量实验。

## 6.2 实验配置

设置以下三种方法。

| Configuration | Refined Entity | Relation Constraint |
|---|---|---|
| Box-based | No | Yes |
| Ours w/o Relation | Yes | No |
| Ours | Yes | Yes |

### 配置一：Box-based

使用相同M0设备身份、类别、包围框、工业坐标系、类别语义、空间关系及查询逻辑。

通过关系查询获得目标设备后，直接返回目标M0包围框内的全部候选高斯。

具体而言，使用现有v2提取流程中的M0粗候选集合，替代最终SAGA精细实例。

这一配置主要验证：

在已经具有设备空间先验和关系筛选能力的条件下，进一步进行亲和特征驱动的精细实例提取是否具有实际价值。

预期观察重点：

- 地面及背景残留。
- 邻近设备混入。
- 设备主体保留。
- Precision及Recall之间的变化。

### 配置二：Ours w/o Relation

直接使用现有v2的设备级精细实例和类别共享语义。

输入与完整方法相同的关系查询，但仅执行目标类别匹配，返回该类别的全部可用精细设备实例。

例如：

查询“冷风机左侧的物料车”。

该配置返回全部可用物料车实例，而完整方法进一步利用左侧关系筛选目标设备。

这一配置主要验证：

即使已经形成较好的三维设备实例，在多个设备具有相同类别语义时，是否仍然需要空间关系来区分目标。

预期观察重点：

- 错误同类设备的数量。
- 目标区域Precision。
- 查询掩膜IoU。
- 类别候选与关系候选之间的差异。

### 配置三：Ours

直接复用冻结的v2完整方法。

利用相同类别语义及空间关系获得目标设备，并返回现有精细三维高斯实例。

## 6.3 消融实验控制条件

三种配置使用：

- 相同的原生3DGS。
- 相同M0先验。
- 相同类别匹配逻辑。
- 相同25条关系查询。
- 相同评价相机。
- 相同参考掩膜。
- 相同三维投影及掩膜生成规则。

重点检查设备实例可用性的影响。

当前Ours有30个可用或局部可用实例。为了明确比较精细实体表达本身的作用，Box-based主消融配置应采用与完整方法相同的精细实例可用性门控，使两者的目标设备身份一致，仅改变最终返回的高斯集合。

可以额外记录允许Box-based使用全部33个粗候选设备时的实际表现，作为真实粗定位能力的补充分析。

两种统计应明确区分。

对于不可用设备、正常空预测和多目标查询，沿用外部对比实验中的统一处理规则。

## 6.4 可选的补充配置

检查项目早期M2模块是否已有可以直接复用的多视角SAM融合实例。

如果已有结果与当前M0设备身份、基础3DGS及评价条件兼容，可以增加：

`M0 + Multi-view SAM + Relation`

即使用多视角SAM融合实例，保留现有类别语义及空间关系查询。

该配置用于进一步比较简单多视角掩膜融合与共享三维亲和特征提取的区别。

如果需要进行新的大规模算法开发或训练，则将其暂缓。

## 6.5 实际评价

对所有配置实际计算：

- Projection mIoU。
- Precision。
- Recall。

同时记录具有解释价值的中间统计：

- 查询前的类别候选数量。
- 关系约束后的目标数量。
- 最终返回的设备ID。
- 实际返回的高斯数量。

定量评价继续采用查询级平均：

首先计算各查询在有效评价视角下的平均指标，再对全部有效查询取平均。

应使用统一冻结的有效评价集合对全部配置重新计算。

实际实验结果可能表现为粗候选具有更高Recall、精细实例具有更高Precision，或者某些困难设备没有得到改善。根据真实结果分析即可。

形成：

# 七、E03：工业关系实体构建机制的局部分析

这是类似于已有工业论文中几何布局、中间表示及局部机制分析的实验。

该实验主要强调实际中间结果的解释能力，而不是额外建立一个独立的实例分割研究任务。

## 7.2 代表性设备选择

从现有全部33个设备中，选择4类具有不同工业结构特点的设备。

建议包括：

| 设备类型 | 展示重点 |
|---|---|
| 装配夹具台或带黑色工件的夹具台 | 多材质、多组成部分的统一设备表达 |
| 多层料架 | 镂空、细杆及相邻设备干扰 |
| 物料车 | 地面、背景与周围高斯的排除 |
| 工作台或分隔式料架 | 原始重建不完整情况下的有效局部实例 |

根据已有真实结果确定具体设备ID。

同时保留至少一个存在明显局限的设备作为补充案例。

### （3）多视角参考及提示

### （4）共享亲和特征响应

### （5）最终三维关系实体

- 最终精细高斯实例。
- 独立设备渲染。
- 完整场景中的实例可见投影。

1. 复杂设备的不同组成部分是否能够作为统一实体保留。
2. 相邻设备及背景是否得到有效排除。
3. 是否存在已经重建但被错误删除的设备结构。
4. 部分重建的设备是否能够形成具有实际意义的局部实体。

高斯数量及剔除比例用于解释方法处理过程，不直接等价为分割准确率。

示意性连线、文字、色标和箭头可以后期绘制，但必须对应真实设备、真实关系及真实计算结果。

亲和度图、选择结果和高斯分布采用真实中间数据。

## 14.4 图片文件输出

- 高分辨率PNG。

- 独立子图。
- 绘图脚本。
- 图像布局配置。
- 原始数据来源记录。
- 对应中英文图注。

建议按双栏论文宽度约170—180 mm设计，主要位图保持300 dpi以上的有效分辨率。

复杂文字、连线、图例和统计图尽量使用可编辑的矢量元素。
