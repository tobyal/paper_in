# M0 v2.1：单视窗高斯漫游与三维设备框

交付日期：2026-11-26（Asia/Shanghai）。

本次按用户最新要求调整第二步。第一步保留原场景选择方式和已确认结果；第二步改为单个高斯三维窗口，在场景内移动、缩放、旋转每个设备框，控制各框显示，最后批量保存。M0 仍只准备粗空间先验，不执行精确实例提取或论文核心算法。

## 实现与数据契约

- 采用本地 Three.js r169 的官方 TransformControls，版本与已有 Three.js/OrbitControls 一致；保留 MIT LICENSE。
- 设备框为中心 + 局部三轴尺寸 + 单位四元数 xyzw。旋转方向是框局部坐标到工业坐标。旧 AABB 按单位旋转解释。
- 选取、角点、框内判定、可选参考相机投影、预览、场景坐标变换、保存、刷新和导出使用同一 OBB 约定。场景坐标发生旋转时，设备框原始世界角点保持不变。
- 新 manifest 标记 object_bbox_schema=obb-xyzw-v1。下游读取器必须使用四元数，不能只比较 center ± size/2。
- 新设备先用 draft_ 临时 ID；切换设备保留所有待修改内容。/api/objects/batch 校验全批后提交一个 SQLite 修订并返回永久 ID 映射。非法对象、过期修订均不产生部分提交。
- “一键保存全部”允许保存草稿；确认身份仍需人工核对，不会自动把草稿变成人工真值。显示/隐藏不改变身份确认；删除保留历史。
- 自动草稿包含全部 pendingObjects，兼容升级前的单对象草稿；保存期间阻止继续拖动，以免覆盖正在提交的编辑。

## 真实高斯画面

新增 roam_service.py / roam_worker.py：在 GPU 3 上常驻加载既有 MWP 2DGS 模型，使用现有官方 GaussianModel、Camera 和 gaussian_renderer。按原始顶点索引选择确认场景内的 549,900 个高斯。支持切换范围外背景；不改写原始 PLY、官方源码或训练结果。

Three 相机采用右/上/后，官方相机采用右/下/前。通过已确认工业变换的逆矩阵及 diag(1,-1,-1) 完成相机转换。独立测试在两个原始训练相机上验证了 R/T 往返一致。

这是服务器渐进渲染：相机移动期间为轻量高斯中心预览；停稳约 180 ms 后请求真实 2DGS JPEG，收到与当前相机一致的画面后替换背景。迟到的旧视角帧被丢弃。不是浏览器本地每帧 Gaussian splatting，网络、模型冷启动和 JPEG 传输影响整体延迟。

官方 rasterizer 即使仅输出 RGB，也要求 CUDA semantics 缓冲。初次子集渲染因未初始化这个缓冲失败；失败日志保留在隔离目录 .jobs/roam_worker.log。修复为明确的全零 CUDA 缓冲，不继承既有语义结果，也未改变核心算法。

## 使用

1. 在第二步漫游，点击“新建对象”后点击设备表面。
2. 用“移动 / 缩放 / 旋转”手柄调整；左侧圆点逐个显示或隐藏。
3. 可连续操作多个设备，最后“一键保存全部”。
4. 基础名称、描述、身份确认和可选 SAM 参考保持原有职责；空间粗框不代表最终设备实例。

源模型在未充分观测的视角仍有孔洞、拖影和模糊；本次未重训、补洞或更改算法。框画在场景上方以便编辑，不执行设备遮挡推理。SfM 单位仍未标定为米。
