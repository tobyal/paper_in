# 漫游时高斯与点云切换修复

日期：2026-11-26。用户要求移动、旋转期间保持高斯画面。本记录覆盖 OBB_ROAMING_REPORT.md 中早期“移动时几何预览、停稳后高斯”的交互说明。

## 原因与修复

旧 cameraChanged 在每次相机变化时立即清除高斯背景并显示中心点云，同时重置 180 ms 防抖计时器。渲染返回后还要求相机版本完全未变，因此持续拖动会一直显示点云。

第二步现在始终隐藏用于拾取的高斯中心几何。相机变化启动连续的官方 2DGS 渲染请求，不等待操作结束；保留一个在途请求，其后的请求只采样最新相机位置。每个完成的有效帧都会显示，即使用户还在拖动。等待后继帧或请求失败时保留上一张高斯画面；首次加载期间等待真实画面，不以点云替代。

导航相机与当前显示相机分开。背景 JPEG、包围框、手柄和鼠标拾取使用同一帧捕获的相机，防止背景暂时滞后而框先移动。开始拖动框时，将导航相机同步到当前显示视角，并丢弃在途的旧导航帧。场景范围变更、切换页面或销毁工作台后不会接受失效的帧。

第一步的原有四视图保持原实现。未改动后端官方 2DGS 算法、模型、已有场景或设备标注。

## 验证

运行 `node m0/tests/test_gaussian_stream.mjs`，10 类调度契约通过：

- 输入持续变化时仍显示已完成帧；最多一个在途请求；后继请求取最新相机。
- 画面和相机成对更新；第二步任何渲染周期都不绘制点云；网络错误保留高斯帧。
- 鼠标事件不反复重置请求计时器；手柄开始操作时同步已显示相机；失效场景帧丢弃。
- 第一步原有点云显示仍可用。

本机浏览器实际旋转、W/A 移动、聚焦和切换旋转手柄后，显示帧号从 1 增至 3，再至 5；视角变化仍为真实 2DGS，浏览器未记录 JS 错误。当前场景包含 642,942 个高斯。截图：本机 logs/m0_continuous_gaussian.jpg。该截图只展示实际页面，不是模拟测试的图像。

修复前保存了正式状态和工作草稿快照：logs/m0_stream_state_before.json、logs/m0_stream_draft_before.json。部署仅替换静态文件，不重启模型服务、不提交标注；验收未拖改设备框。旧静态文件备份位于服务器 backups/m0_before_continuous_gaussian_20261126/。

实际刷新速度仍受服务器 GPU、网络及 JPEG 解码影响。本次消除了表示方式切换，没有声称实现浏览器本地 60 FPS splatting；慢帧时画面与框一起等待下一张高斯帧。
